# CSSWG Drafts Tools

This directory contains build scripts, editor utilities, and configuration files for the `w3c/csswg-drafts` repository.

## Overview

| File / Directory | Category | Purpose |
| --- | --- | --- |
| [`build-index.py`](build-index.py) | CI / Site Build | Generates the root `index.html`, unversioned/legacy symlinks, redirects, and `timestamps.json` |
| [`build-markdown.py`](build-markdown.py) | CI / Site Build | Renders Markdown files (such as explainers) in subdirectories to HTML via `cmark-gfm` |
| [`css-combiner/`](css-combiner/) | CI / Site Build | Builds the combined `all-css` specification (`index.html`, `properties.html`, `index.md`, and panel JSON data) |
| [`specs-config.toml`](specs-config.toml) | Shared Config | Shared current-work level overrides and legacy path redirects for `build-index.py` and `css-combiner/` |
| [`requirements.txt`](requirements.txt) | Shared Config | Python dependencies (`bikeshed` and vulnerability-pinned transitive packages) for CI pip caching |
| [`xcommit.pl`](xcommit.pl) | Editor Tool | Applies working-tree diffs from one spec level to other levels of the same module and commits them |
| [`issuegen.pl`](issuegen.pl) | Editor Tool | Converts plaintext (`.txt` / `.bsi`) issues lists into filterable HTML Disposition of Comments pages |
| [`ua-capitalization.sh`](ua-capitalization.sh) | Editor Tool | Lowercases `"User Agent"` to `"user agent"` in spec source files |
| [`bikeshed-curl`](bikeshed-curl) | Editor Tool | Builds `Overview.bs` to `Overview.html` via the W3C Spec Generator API using `curl` |

## CI & Site-Build Tools

These tools run automatically during deployment via [`.github/workflows/build-specs.yml`](../.github/workflows/build-specs.yml) to build and publish [drafts.csswg.org](https://drafts.csswg.org/).

### `build-index.py`

Generates the top-level specification listing, URL symlinks, redirects, and metadata for the published site.

- **Run from repository root:**
  ```sh
  python ./bin/build-index.py
  ```
- **Dependencies:** Python 3.11+ (`tomllib`), `bikeshed`, `git`.
- **What it does:**
  - Scans top-level directories for `Overview.bs` or `Overview.html` (ignoring `css-module`), collects Disposition of Comments files (`issues-*.html`, excluding `*.bsi.html`), and detects explainer Markdown files (`explainer*.md` or `.md` files inside `explainer/` / `explainers/` directories, linking to the HTML generated by `build-markdown.py`).
  - Groups multi-level specs by shortname, selects each group's "Current Work" spec using `[current_work_exceptions]` from [`specs-config.toml`](specs-config.toml) (falling back to the lowest level whose `workStatus != "completed"`, or the highest level if all are completed), and creates unversioned symlinks (plus `css` → latest CSS Snapshot).
  - Writes `timestamps.json` mapping spec directories (and unversioned symlinks) to the Unix timestamp of the most recent git commit touching `Overview.bs`.
  - Creates legacy path redirect symlinks from `[legacy_redirects]` in [`specs-config.toml`](specs-config.toml), HTML meta-refresh redirects for cross-origin specs (`cssom-values`, `cssom-values-1` → `drafts.css-houdini.org`), and HTML meta-refresh redirects for old CSS 2.1 chapter pages under `css2/`.
  - Writes the root `index.html` with search filtering, Recent/Grouped views (persisted in `localStorage`), activity indicators, responsive/dark-mode styling, and links to the combined `all-css` specification.

### `build-markdown.py`

Converts Markdown documents in non-hidden subdirectories (primarily spec explainers) into standalone HTML pages.

- **Run from repository root:**
  ```sh
  python ./bin/build-markdown.py
  ```
- **Dependencies:** Python 3, [`cmark-gfm`](https://github.com/github/cmark-gfm) on `PATH`.
- **What it does:**
  - Finds all `*/**/*.md` files (skipping hidden paths starting with `.`) that do not already have a sibling `.html` file.
  - Renders each file with `cmark-gfm` (`table`, `autolink`, `strikethrough`, `tasklist`, and `--unsafe` enabled), converts GitHub Flavored Markdown alert blockquotes (`> [!NOTE]`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`) into styled `.admonition` blocks, sets `<title>` from the first `# ` heading, and writes `<name>.html`.

### `css-combiner/`

Builds a single combined CSS mega-specification from the active modules in the repository, intended both for human full-text search and for AI agents needing unified spec context.

- **Run from repository root (or inside `bin/css-combiner/`):**
  ```sh
  python ./bin/css-combiner/combine.py
  ```
- **CLI options:**
  - `--config PATH` — Path to the combiner config file (defaults to `bin/css-combiner/config.toml`).
  - `--output-dir PATH` — Output directory (defaults to `<repo-root>/all-css`).
  - `--specs SPEC [SPEC ...]` — Combine only a subset of spec directories (useful for local testing).
- **Dependencies:** Python 3.12+, `git`, and the packages in [`css-combiner/requirements.txt`](css-combiner/requirements.txt) (`bikeshed`, `lxml`).
- **Outputs (written to `all-css/` by default):**
  - `index.html` — Combined HTML specification with disambiguated IDs (`<spec-id>:<id>`), rewritten cross-spec links and relative asset paths, merged Table of Contents, consolidated Security & Privacy section, combined Internal/External Indexes, combined Property Index, Bikeshed diagnostic appendix, and interactive definition panels / reference hints.
  - `properties.html` — Standalone document containing only the combined Property Index tables, with property and spec links targeting `./index.html`.
  - `dfn-panels.json` and `ref-hints.json` — Sidecar JSON datasets lazy-loaded by `all-css/index.html`.
  - `index.md` — Clean Markdown serialization of the combined specification with human-only UI chrome and redundant indexes omitted.
- **Key files inside `css-combiner/`:**
  - [`combine.py`](css-combiner/combine.py) — CLI entrypoint.
  - [`config.toml`](css-combiner/config.toml) — Controls which specs are included and their ordering (`[specs.<dir>]`, with optional `diff_of` for delta specs), intentionally omitted directories (`[skip]`), and superseded-level link rewrite targets (`[replaced]`). Snapshot directories (`css-YYYY`) are skipped automatically. Any newly added spec directory not listed in `config.toml` is logged as an error and displayed in a dismissable banner in `all-css/index.html` without failing CI.
  - [`css_combiner/`](css-combiner/css_combiner/) — Implementation package (`pipeline.py`, `config.py`, `builder.py`, `extractor.py`, `rewriter.py`, `indexes.py`, `assembler.py`, `markdown_writer.py`, `models.py`).
  - [`requirements.txt`](css-combiner/requirements.txt) / [`requirements-dev.txt`](css-combiner/requirements-dev.txt) — Runtime and development dependencies.
  - [`lint`](css-combiner/lint), [`pyproject.toml`](css-combiner/pyproject.toml), [`mypy.ini`](css-combiner/mypy.ini) — Linting, formatting, and type-checking script (`ruff`, `black`, `mypy`, `pylint`) for `css-combiner/`.
  - [`impl-plan.md`](css-combiner/impl-plan.md) — Original design specification and implementation notes.

### `specs-config.toml`

Shared TOML routing configuration loaded by both [`build-index.py`](build-index.py) and [`css-combiner/`](css-combiner/):

- `[current_work_exceptions]` — Overrides which level of a multi-level specification represents its unversioned "Current Work" shortname (either an integer level or `"last"` to always pick the highest level/snapshot).
- `[legacy_redirects]` — Maps retired or renamed spec folder names to their current local targets, used both for symlinks on `drafts.csswg.org` and for resolving cross-spec links in `all-css`.

### `requirements.txt`

Lists `bikeshed` along with minimum-version pins on transitive Python dependencies (for vulnerability mitigation). Also picked up by `actions/setup-python` (`cache: 'pip'`) in [`.github/workflows/build-specs.yml`](../.github/workflows/build-specs.yml).

## Editor & Maintenance Utilities

### `xcommit.pl`

Cross-level commit helper for specifications that maintain multiple active levels (e.g., `css-grid-1`, `css-grid-2`, `css-grid-3`).

- **Usage:**
  ```sh
  bin/xcommit.pl css-grid-1
  # or from inside a spec directory:
  ../bin/xcommit.pl .
  ```
- **Dependencies:** Perl, `git`, `patch`.
- **What it does:**
  - Assumes `<shortname>-<N>` directories one level below the repository root.
  - Prompts for the lowest level to patch (defaulting to levels higher than the source directory), exports unstaged changes from the source directory with `git diff -U3 --minimal`, and applies them to each target level directory via `patch -p2`.
  - If all patches apply cleanly, prompts for `git commit` arguments (e.g., `-m "..."` or `--amend`) and commits across all matching level directories. If any patch fails, aborts before committing so conflicts can be resolved manually.

### `issuegen.pl`

fantasai's Issues List Generator. Converts a plaintext (`.txt` or `.bsi`) issues list into a color-coded, interactively filterable HTML Disposition of Comments (`.html`) document with W3C mailing-list thread and `mid:` links.

- **Usage:**
  ```sh
  bin/issuegen.pl path/to/issues-lc-2023.txt   # generates issues-lc-2023.html
  bin/issuegen.pl                              # prints the input template
  bin/issuegen.pl help                         # prints full format documentation
  ```
- **Dependencies:** Perl.
- **Note:** In CI, `.bsi` and `issues-*.txt` files are now built automatically with `bikeshed issues-list`.

### `ua-capitalization.sh`

Automates lowercasing `"User Agent"` to `"user agent"` (preserving sentence-initial `"User agent"` after `. ` or `Note: `) in accordance with the [2021-04-08 CSSWG resolution](https://logs.csswg.org/irc.w3.org/css/2021-04-08/#e1402191).

- **Usage:**
  ```sh
  bin/ua-capitalization.sh css-foo-1/Overview.bs
  ```
- **Dependencies:** Bash, GNU `sed` (uses `sed -i` without a backup extension), `grep`.
- **What it does:** Performs in-place replacements on the given files and then runs `grep -R "User Agent"` to report any remaining occurrences that require manual review.

### `bikeshed-curl`

Builds `Overview.bs` in the current working directory into `Overview.html` via the remote W3C Spec Generator API (`https://www.w3.org/publications/spec-generator/`) without requiring a local Bikeshed installation.

- **Usage:** Run from inside a spec directory:
  ```sh
  ../bin/bikeshed-curl
  ```
- **Dependencies:** `curl`.
- **What it does:** Sends `Overview.bs` twice — first with `output=messages` to print Bikeshed diagnostics to stdout, and then with `die-on=nothing` to write the compiled HTML to `Overview.html`.
